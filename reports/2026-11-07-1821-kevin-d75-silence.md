# Kevin: D75, silence on non-questions in Provläge and Auto

Date: 2026-11-07 · Assignment: Aron (chat), owner decision D75, after his first device test (Provläge, iPhone + AirPods, 17:46)
Commit: `a9f47fc` · Deploy backend: run 42395742420 **green** · Live: **answer v47** (tts v20)

## What was asked
In the device test the server answered fragments that were not questions ("Äh, syntes. Det är det enda jag vet.",
"Det är en annan. Ja, obrutet. Kom igen.") with long, vague meta answers ("Det låter som att du tänker på…",
"Berätta gärna ordet…"). D75:
1. In Provläge (`mode: "tutor"`) and Auto, a fragment that is not a question or request, or is too broken to
   interpret, gets no answer at all (`answered:false`, no speech). Never a meta answer, never a request for clarification.
2. Misheard subject words are mapped to the nearest plausible topic from the context and answered, without
   mentioning the interpretation.
3. Live-eval cases: the two fragments above and 10 own broken STT fragments. Measure the share of silent replies to
   non-questions and check that real questions are still answered.

## What was built
| # | Change | Status |
|---|---|---|
| 1 | **Provläge:** the tutor prompt no longer has the confirmation rule. Its new SILENCE rule says: reply only `[[TYST]]` to fillers, reactions, remarks to others, half sentences with no topic and fragments too garbled to map to any subject. Never comment on what the student seems to mean, and never ask for clarification. A reply to the last check question, "vet inte", "nästa fråga", "mer", a bare term and anything with a concrete topic is always answered. The new `SilenceTap` (speech.ts) catches the marker, also after the relation tag. The stream then stops, and the reply is `meta` with `is_question:false`, no delta, `done.answered:false` and status `not_question`, exactly like a non-question in Auto. The app already handles this as silence (`AnswerEngine`: `notAQuestion` → `answerSkipped`). | verified in tests + live |
| 2 | **Meta filter in code** (`MetaGate`, `isMetaReply`), Provläge and Auto only. Sentences that start with "Det låter/verkar som att du…", "Berätta gärna…", "Kan du förtydliga/upprepa…", "Menar du…", "Vad menar du…", "Jag förstår/uppfattade inte…", "Du verkar tänka…", "Om du menar…" and similar are dropped. If nothing else is left, the reply is silence. If a real answer follows, only that is spoken. Text mode and the personas are unchanged. Text mode keeps its confirmation question. | verified in tests + live |
| 3 | **Meta later:** in Provläge and Auto, `meta` with `is_question:true` is now sent together with the first spoken text, no longer on its own first. That is how the server can still say "stay silent" after the model has started. The order meta → delta → done is the same for the app. | verified in tests |
| 4 | **Auto never asks back:** with low confidence (below `confidence_threshold`), `is_question` is now `false`, so the reply is silent and is not "Menar du …?". This is done in the prompt and in the parser. The auto prompt's `is_question` rule now also counts fillers, reactions, half sentences and garbled fragments as non-questions. The prompt example "roten av hun" is moved to text mode, and an auto non-question example was added. | verified in tests + live |
| 5 | **Misheard subject words (all direct modes and Auto):** a new rule says that a word which is not a sensible topic as written is mapped to the nearest plausible subject term from `<recent_qa>`, `<active_topic>`, `<goals>`, `<prep_terms>` and `<transcript>`, and answered directly, never saying it was interpreted. The prompt example is my own ("tek tonik" → plattektonik). It is not one of the eval fragments, following the hold-out rule. | verified live (tyst-01, tyst-16) |
| 6 | **Live-eval:** a new category `tystnad` with 20 cases: the two device-test fragments, 10 own broken non-questions (6 Provläge, 4 Auto), 7 real questions that must still be answered (including a one-word reply and "vet inte" to a check question, "jon bindning", "eh, kan du förklara typ, cellandning"), and one "either" case. Cases support `mode`, `context_qa` (seeded history) and `expect` (`silent`/`answer`/`either`). Every spoken answer is also checked for meta openings. The report line is "Tystnad (D75): X/Y icke-frågor fick inget svar; X/Y riktiga frågor besvarades." | done |

The system prompts grew: Auto is now 11 711 characters (it was under 11 200 before), and Provläge is 9 488. They are cached, so the cost is about the same. The test limit was raised from 11 200 to 12 000.

## Known limits and risks
- **More silence can also be wrong silence.** A real but very short question in a noisy room could now be dropped, where it used to get a vague answer. 8/8 real questions were answered here, but the sample is small. Oscar's next round should include more borderline cases, such as one-word terms with no history.
- The meta filter is a list of phrases. New wordings can slip through, and a teaching sentence that happens to start with "Om du menar …" is dropped.
- When the model writes a real answer starting with "Det är en bra start, …", it is spoken. That is praise, not meta, and it is allowed.
- The app now gets `meta` later in Provläge and Auto, together with the first text. This is **untested on device**, but the order is unchanged, so `AnswerEngine` should behave the same.
