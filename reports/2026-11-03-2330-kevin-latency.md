# Kevin Malone — backend latency (D28): first answer text under 700 ms

Date: 2026-11-03 · Assignment: top of `prompts/2026-11-03-mvp-sprint-backend.md` · Area: `backend/` (Edge Function code)

**Result: big improvement, target not yet met.** First answer text p50 **1 590 -> 980 ms**, p90 **2 005 -> 1 079 ms** (measured). A further step (v3) is deployed but unmeasured. The 700 ms goal is not reached by what is measured.

## Measured (all numbers **verified live**, 30 Swedish short prompts, `push_to_talk`)
Method: a temporary Edge Function inside Supabase (eu-central-1) played client: anonymous sign-in, then the 30 prompts sequentially against the real `/answer` with real Claude Haiku 5.5, SSE parsed, time to first `delta`. The build container cannot reach `*.supabase.co`, so `deno task ttft` could not be used. Network from the client to the function is therefore *inside* Supabase; a phone adds its own network time on top.

| | v1 before | v2 after step 1 |
|---|---|---|
| **Time to first answer text, p50** | **1 590 ms** | **980 ms** |
| p90 | 2 005 ms | 1 079 ms |
| max (first call, cold) | 4 353 ms | 2 326 ms |
| Server-side time to first text, p50 | 1 277 ms | 630 ms |
| Time to full answer, p50 | 1 886 ms | 1 370 ms |
| Input / output tokens per answer | 1 447 / 78 | 512 / 38 |
| Est. cost per answer (Haiku 5.5, $0.10/$0.50 per MTok) | $0.00018 | $0.00007 |

Where the time went in v1 (from the new `breakdown` and probes): three sequential limiter RPCs ~450 ms (each REST call from the function costs 150-240 ms: function in Frankfurt, DB in Stockholm); Anthropic ~120-150 ms away; JSON header ~195 ms; 1 450-token prompt; client-vs-server gap ~320 ms, explained by **fresh isolates: 29 of 30 requests were cold**, so module import is paid per request.

## What changed (code only, `backend/`)
1. **Direct mode** for `push_to_talk`/`text`: no JSON header, short prompt, meta sent up front (`confidence:1`). `auto` unchanged.
2. **Parallel limiter**: one RPC `check_rate_limits` for minute/day/global, run at the same time as the LLM call; no byte reaches the client until both pass; denial aborts the LLM call. A per-isolate guard bounds speculative starts. (Same for `/tts` characters.)
3. **Prompts** 1 450 -> 510 tokens, `cache_control` set (Haiku 5.5 caches from 512 tokens; the direct prompt is just under, so no cache hit yet — verified: `cache_read_tokens: 0`).
4. **v3, deployed, unmeasured:** official SDK and supabase-js replaced with `fetch` clients (same `anthropic-version` 2026-10-21 and body as the SDK sent; module import cost measured locally ~70 ms + ~75 ms per isolate). Upstream pre-connect at boot; `GET` + `x-warm: 1` keep-alive on `answer`/`tts`.
5. Timing `breakdown` in every `done` event and log line; cost estimate now cache-aware.
6. Tests: 75 Deno tests green (parallelism proven by timing test, denial aborts upstream, local guard, warm endpoint, fetch-based Anthropic client incl. error mapping and SSE parsing).
